## Übung (pwn add to sub)
 
Ich hab in gdb mit disas main nachgeschaut wo die Addition passiert:  
```0x0000555555555224 <+196>:   add    -0xc(%rbp),%eax```  
 
Dann hab ich mit x/3xb den Opcode ausgelesen:  
```0x555555555224:  0x03  0x45  0xf4```  
0x03 ist der Opcode für add, der entsprechende Opcode für sub ist 0x2B. Die restlichen Bytes bleiben gleich weil sie den Operanden beschreiben.  
 
Patch:  
```(gdb) set {unsigned char}0x0000555555555224 = 0x2b```  
 
Kontrolle:  
```(gdb) x/i 0x0000555555555224  ```
=> sub    -0xc(%rbp),%eax  
 
Test: Eingabe 5 und 3 → statt 8 kommt jetzt 2 raus. Hat funktioniert.  

## Übung (Binary File Patching I)
 
Mit objdump -d pwcheck den Disassembly von main analysiert und die relevante Stelle gefunden:
```11a5:   0f 84 95 00 00 00   je  1263 <main+0xf3>```
 
Der je-Befehl ist hier 6 Bytes lang (0f 84 + 4 Bytes Sprungziel). Wenn das Passwort falsch ist, springt er zu 1263 und überspringt den erfolgreichen Pfad.  
Man muss diesen Sprung deaktivieren.
 
Mit ```hexedit pwcheck``` zum Offset 0x11c8 gesprungen (Ctrl+G) und alle 6 Bytes mit 0x90 (nop) überschrieben:  
Vorher: ```0f 84 95 00 00 00 ``` 
  
Nacher: ```90 90 90 90 90 90 ```   
 
Gespeichert mit Ctrl+X und das Programm getestet → die Passwortabfrage wird jetzt unabhängig von der Eingabe übersprungen. 
 
Das Passwort (per ROT13 im Code sichtbar) lautet: ```G7pL9xQ2mR4tZcH```
